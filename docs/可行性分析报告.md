# 可行性分析报告

版本：`0.1.0`。日期：2026-10-11。状态：首轮分析，原型尚未实施。

## 1. 结论

DeskTrace 在 Windows 11 上作为单用户本地工具具有实施价值。启用后的前台应用使用和资源管理器文件夹浏览，可以通过公开系统接口建立自己的记录。首次运行时获取应用清单和部分系统日期也可行。

限制在于历史完整性：Windows 没有一个公开、统一、保证完整的接口，能够列出所有文件夹与所有应用的真实“最近打开时间”和“首次安装时间”。因此，产品应以持续观察为主；缺失时间显示未知，安装日期保留来源和含义，长期未使用结果定位为整理候选。

**推荐先做 Windows 11 技术原型，再建立正式工程。** 活动标签页定位、前台进程归属和普通用户权限覆盖，是决定首期可交付范围的三个验证点。

## 2. 用户需求与业务价值

个人电脑长期使用后会积累项目文件夹、下载目录和已安装应用。单凭修改时间、占用空间或应用名称，很难判断哪些内容值得整理。DeskTrace 提供最近观察到的使用时间、观察时长和安装日期线索，帮助用户自己核对。

首期用户是当前登录的 Windows 用户。用户的核心操作是查看、筛选、排除和导出；清理动作由用户在资源管理器或 Windows 应用设置中完成。

## 3. 各类数据的可行性

| 目标 | 拟用数据源 | 判断 | 产品约束 |
| --- | --- | --- | --- |
| 应用最近使用 | 前台窗口事件、进程路径或包身份 | 可行，需验证归属 | 记录观察时间；不等同精确启动时间 |
| 文件夹最近浏览 | Explorer Shell COM 接口 | 有条件可行 | 首期只覆盖已验证的资源管理器场景 |
| Win32 应用清单 | 当前用户与本机卸载注册表，区分 32/64 位视图 | 可行 | 安装项不一定有可执行入口；不能只按名称匹配 |
| Win32 安装日期 | 注册表 `InstallDate` | 部分可用 | MSI 日期可能被更新或修复改写，原始安装时间未必可得 |
| MSIX 应用与日期 | 当前用户 PackageManager 与 `Package.InstalledDate` | 可行，需验证过滤和权限 | 日期表示包安装或最后更新，包不等于单个应用入口 |
| 便携应用日期 | 可执行路径、自行首次发现 | 只能部分满足 | 没有标准安装记录，安装日期显示未知 |
| 启用前使用历史 | Recent、Jump List 等系统线索 | 不能保证完整 | 列为后续可选能力，不作为首期判断依据 |
| 长期未使用候选 | 自行记录、观察区间、来源健康状态 | 可行 | 结论必须说明支持范围和记录中断 |

微软对 MSI `InstallDate` 的定义包括产品最近维护时间；[官方说明](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key)是不能将该值一律标为首次安装时间的依据。MSIX 的 [`InstalledDate`](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.package.installeddate?view=winrt-26100)同样可能表示最后更新。

## 4. 不采用文件系统访问时间的原因

NTFS 最后访问更新可以关闭，并且访问时间更新可能延迟。即使启用，目录枚举和程序读取也不等于用户在资源管理器中打开目录。[微软文件系统行为说明](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/fsutil-behavior)说明了配置和更新行为。

本机实测最后访问更新已关闭。因此不更改该设置，也不使用目录 `LastAccessTime`、创建时间或修改时间替代最近浏览时间。文件监视器捕获文件变化，不能单独证明打开行为。

## 5. 采集路径与局限

### 5.1 应用

通过 [`SetWinEventHook`](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)监听当前桌面的前台切换；采用进程外回调，由专用消息循环线程接收。读取窗口所属进程，再关联可执行路径、包身份与应用清单。

前台切换是使用信号，不是进程启动信号。后台服务、升级器、浏览器子进程或托盘常驻，不应仅凭运行状态刷新应用最近使用时间。启动器与被启动应用分别识别，映射不确定时保留独立入口。

锁屏、休眠与用户长时间无输入时停止活跃刷新。最后输入时间只用于当前会话的空闲判断，不采集按键内容；[接口文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)说明了会话限制。

### 5.2 文件夹

[`IShellWindows`](https://learn.microsoft.com/en-us/windows/win32/api/exdisp/nn-exdisp-ishellwindows)可访问已注册的 Shell 窗口，但窗口枚举本身不足以保证 Win11 活动标签页准确。原型需结合活动窗口、Shell view 和文件系统项目识别导航结果。

只有前台活动标签页解析成功的真实文件夹进入记录。后台标签页、虚拟“此电脑”或搜索结果不冒充普通路径。不能可靠辨别活动标签页时，标记采集不可用，不将所有标签页都算作打开；必要时另行评估 UI Automation。

第三方文件管理器、应用内部文件选择器、WSL 内部目录访问和文件内容读取首期不在覆盖范围。用户打开 IDE 内某个目录，也不自动视为资源管理器浏览。

### 5.3 历史线索

[`SHAddToRecentDocs`](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shaddtorecentdocs)体现了系统近期项目的部分记录方式，但其存在应用选择退出等限制；Recent 也不是全体应用启动历史。Jump List 等历史导入即使后续实现，也只能作为单独线索，不能用“没有记录”证明未使用。

UserAssist、Prefetch、BAM 等数据不作为首期依赖：解析与覆盖不能按稳定业务接口承诺，部分来源还需要更多权限。本次不实施读取或修改。

## 6. 安装日期与长期候选的处理

默认长期阈值为 90 天，支持 30/90/180 天和 1～3650 天自定义。阈值是产品默认假设，可调整。

时间字段分开保存：最近观察到的使用、系统安装或更新日期、首次发现、开始观察。安装日期不参加“最后使用”运算。初次扫描见到老安装项、但没有使用记录时，显示未知或观察不足。

达到阈值且记录较旧的对象列为候选；观察期内一次使用也没记录到的对象另列。采集暂停、退出、权限失败和模块异常都形成记录中断，结果注明中断。即便记录连续，也只支持“在已覆盖的观察范围内未记录到使用”，不能保证现实中所有方式均未使用。

## 7. 技术、运行与成本

Tauri 2 + Rust 可承载原生采集、托盘与本地界面，Vue 3/TypeScript 适合列表和设置。SQLite 无独立服务，符合单用户离线存储；选择理由见[技术选型说明书](技术选型说明书.md)。

普通用户权限运行，不默认安装 Windows 服务。采集开始前由用户启用，开机启动可选；关闭主窗口时驻留托盘，明确退出后停止。数据不上传，不读取文件正文、浏览器内容或窗口标题。

首期预计 18～28 人日：原型 3～5、设计和工程 4～6、功能开发 6～9、验证与发布 5～8。该估算基于单人开发、Windows 11 x64、无云端与无直接清理功能，不是交付承诺。代码签名及分发费用未询价，不计入估算。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 活动标签页识别失败 | 文件夹记录串页或漏记 | 原型先行，未通过的场景显式停用，不伪造数据 |
| 应用身份误合并 | 最近使用时间归错应用 | 多入口表、包身份、人工修正；模糊匹配不自动合并 |
| 安装日期为空或更新覆盖 | 安装龄不准确 | 显示含义与精度，保存日期快照，缺失值留空 |
| 采集未运行 | 使用历史不连续 | 模块健康状态、心跳、中断标识、观察不足提示 |
| 系统时钟变化 | 候选判断偏移 | UTC 存储、单调时钟测时，异常区间标为未知 |
| 重命名、移动、外置盘断开 | 路径误识别或对象失联 | 可用时读取文件标识，无法确认时保留未解析状态 |
| 路径包含私人信息 | 本地记录和导出泄露 | 用户可排除和清除；日志脱敏；导出明确列出字段 |
| 高频事件、COM 卡顿 | CPU、写盘或界面延迟 | 专用工作线程、去重、批量写入、失败退避 |

## 9. 原型通过条件

1. 当前 Windows 构建中，单窗口、多窗口、标签切换与地址栏导航能正确区分活动文件夹；100 次支持范围内操作无错归属，识别不少于 95 次。
2. 对 10 个代表应用各执行 10 次前台使用，身份匹配不串应用，明确展示未知项；普通权限失败有状态反馈。
3. Win32 和 MSIX 日期能读取、解析、标注含义；缺失日期不会被文件时间或首次发现时间填补。
4. 锁屏、休眠、暂停与异常退出不会把后台运行刷新为用户使用，缺口可在恢复后识别。
5. 资源占用达到测试计划中的待测目标；未达标时先调整采集策略。

若关键场景未通过，先修改首期范围与相关文档，再推进产品开发，不提前承诺全覆盖。
