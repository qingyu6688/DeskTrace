# 技术选型说明书

版本：`0.2.0`。日期：2026-10-11。状态：初始化依赖已固定，采集方案仍待原型。

## 1. 选型结果

| 层次 | 初选 | 用途 |
| --- | --- | --- |
| 产品平台 | Windows 11 x64，当前用户会话 | 首期验证范围，其他系统后续评估 |
| 桌面框架 | Tauri 2 | 窗口、托盘、IPC、安装包 |
| 原生后端 | Rust stable，MSVC 工具链 | 系统采集、业务规则、持久化 |
| 前端 | Vue 3 + TypeScript 严格模式 + Vite | 本地界面、类型检查和构建 |
| 路由与状态 | Vue Router + Pinia | 页面导航、采集与任务状态 |
| UI 组件 | Naive UI，统一中文文案 | 表格、表单、弹窗和反馈 |
| Windows 接口 | `windows` crate，按所需 API 开 feature | Win32、COM、WinRT 绑定 |
| 数据库 | SQLite + `rusqlite`，内置 SQLite | 单用户本地数据，单写入线程 |
| 数据序列化 | `serde` + `serde_json` | 结构化 IPC 与设置 |
| 时间与错误 | `time`、`thiserror`，入口按需 `anyhow` | UTC 转换和分层错误处理 |
| 日志 | `tracing` 与文件轮转组件 | 脱敏诊断 |
| 前端验证 | Vitest + Vue Test Utils，ESLint + vue-tsc | 工具和组件测试、静态检查 |
| 原生验证 | Cargo test/fmt/clippy + Windows 实机用例 | 数据与系统行为验证 |
| 包管理 | pnpm | 固定锁文件并统一开发命令 |

初始化实际依赖由 `frontend/package.json`、`backend/Cargo.toml` 和各自目录下的锁文件管理，精确固定直接依赖。Vue `3.5.43`、Vite `8.3.4`、TypeScript `6.0.3`、Tauri Rust/API `2.12.2`、CLI `2.12.1`、`rusqlite 0.40.2`；没有采用 Tauri 3 alpha。TypeScript 7 超出当前 typescript-eslint 的 peer 范围，因此使用 6.0.3。

Naive UI、路由和 Pinia已用于界面；窗口采集所需 `windows` crate、日志轮转与导出库尚无调用需求，暂不引入。`sha2` 用于迁移校验和，`uuid` 用于对象/事件 ID。Rust 工具链保持 stable，当前实测 1.96.0。

## 2. 桌面方案比较

| 方案 | 适用优势 | 本项目代价 | 判断 |
| --- | --- | --- | --- |
| Tauri + Rust + Vue | 原生采集与 Web 界面在同一工程；符合 Rust 工具优先约定 | COM/WinRT 与多标签页仍需原型；依赖 WebView2 | 初选 |
| C# + WPF / WinUI | Windows 生态与系统接口集成直接 | 引入另一套 UI 与工程规范；WinUI 分发仍需评估 | 原型受阻时的主要备选 |
| Electron + TypeScript | Web 开发顺手，桌面生态成熟 | 原生采集仍要额外桥接；本项目仍需验证资源占用 | 本轮不选 |
| Python + Qt | 便于快速探索 | 常驻采集、打包和运行时维护需额外工作 | 可用于实验，不作为发布主栈 |
| 浏览器页面 + HTTP 服务 | 页面开发简单 | 浏览器不能独立完成所需系统采集，要增加本地服务 | 不适合首期桌面形态 |

选择 Tauri 的依据是工程职责匹配，不以尚未测量的安装包大小或内存数字作为结论。Windows 开发需要 C++ Build Tools、Rust 与 WebView2，见[官方前提](https://v2.tauri.app/start/prerequisites/)。本机已检出这些前提的安装信息，仍须首次编译验证。

## 3. SQLite 与默认 MySQL 的取舍

项目规范默认 MySQL。本项目是无账户、无云端、单机单用户工具，先采用 SQLite，作为有理由的技术例外。

| 项目 | SQLite | MySQL |
| --- | --- | --- |
| 运行前提 | 进程内数据库 | 独立数据库服务 |
| 用户配置 | 本地数据目录 | 服务地址、端口、账号与凭据 |
| 离线使用 | 直接使用本地文件 | 需保证服务可用 |
| 首期并发 | 单写线程与本地查询足够，需实测 | 当前需求用不到服务端多用户能力 |
| 运维 | 本地备份、迁移与恢复 | 还需服务安装、升级与安全配置 |
| 后续多人协作 | 需要新同步或服务端设计 | 更适合集中存储，但不能直接暴露数据库给客户端 |

SQLite 官方将本地应用存储列为适用场景，见[适用范围](https://sqlite.org/whentouse.html)。未来若增加多设备同步或集中管理，再设计后端 REST API 和 MySQL；不让首期客户端承担数据库服务运维。

采用 `rusqlite` 的原因是查询量有限、SQL 可审查、便于事务和迁移；同步操作放入专用数据库线程，不阻塞界面或事件回调。暂不引入 ORM。

计划启用 WAL、外键和有限忙等待。数据库只放本地磁盘，不放网络共享；在线备份使用数据库备份接口，不能直接复制运行中的主文件。[WAL 官方文档](https://sqlite.org/wal.html)说明了并发、共享内存与伴随文件要求。

## 4. 数据采集选型

| 需求 | 选择 | 不采用的捷径 |
| --- | --- | --- |
| 最近应用使用 | 前台事件 + 低频活跃校验 + 进程身份映射 | 将所有进程存在视为使用 |
| 最近文件夹浏览 | Explorer 活动 Shell view + 2 秒前台导航采样 | 使用目录访问/修改时间 |
| Win32 清单 | HKCU/HKLM 卸载项，显式读注册表视图 | `Win32_Product` 全量查询 |
| MSIX 清单 | 当前用户 PackageManager，按入口和包属性过滤 | 枚举其他用户全部安装信息 |
| 日期 | 保存原始来源、日期精度与含义 | 缺失时取安装目录创建时间 |
| 历史导入 | 后续可选适配器，单独保存线索 | 默认解析取证数据并认为完整 |

`Win32_Product` 查询可能触发安装一致性检查，因此不用于只读清单扫描，见[微软说明](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/msiprov/win32-product)。

文件夹 COM 适配器只使用公开接口；Windows 11 标签页无法确认时返回未支持。UI Automation 属于备选实验，不能靠解析中文或英文窗口标题推断路径。首期不采用驱动、DLL 注入或管理员常驻服务。

## 5. IPC 与权限

前端请求统一放在 `frontend/src/api/`，组件调用服务封装。Rust 后端校验所有参数、目录选择凭据和对象身份。数据库、系统采集和文件操作不直接开放给 WebView。

首期无 HTTP 端口，使用 Tauri IPC；这是对通用 RESTful 接口约定的桌面场景调整。接口返回保持统一 `code/message/data`，具体见接口设计文档。

Tauri capability 约束窗口和插件权限，见[官方说明](https://v2.tauri.app/security/capabilities/)。自定义命令也必须纳入应用权限清单；不能假设仅添加 capability 文件就自动限制全部 `invoke_handler` 命令。

只加载打包的本地前端内容，发布包不载入远程页面，不提供任意 Shell 命令、任意 SQL 或任意文件读写接口。

## 6. 首期暂缓

云端同步、用户登录、Spring Boot/FastAPI 服务、MySQL 部署、自动删除和直接卸载均无当前需求，暂不引入。文件夹大小递归统计、第三方文件管理器、macOS/Linux 采集和历史取证解析另行评估。
