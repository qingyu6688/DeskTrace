# 用户使用手册

版本：`0.6.0`。日期：2026-10-11。状态：桌面界面已接入真实本地数据；安装包尚未发布。

## 当前版本如何启动

在项目根目录执行 `pnpm --dir frontend tauri dev` 启动桌面程序。概览和列表读取本机数据；点击“开始记录”后启用采集。应用列表与“桌面与文件夹”支持搜索、筛选、修改查询阈值和导出，点击一行查看轨迹与判断依据。

设置、范围、排除和采集意图保存在本地，重新打开仍生效。单独执行 `pnpm --dir frontend dev` 只预览网页，浏览器没有本机访问能力，会提示未连接并保持空清单。完整启动说明见 [前端实现说明](前端实现说明.md)。

开机启动、原生定位、真实导出和清除已提供界面入口。备份恢复界面、安装与卸载流程尚未提供；原生操作的完整实机验收进度见 [功能完成情况](功能完成情况.md)。

## 1. 产品可以提供的信息

DeskTrace 在你启用后记录应用前台使用和资源管理器文件夹浏览，帮助筛选值得整理的内容。列表会显示最近记录时间和应用的系统安装/更新日期。

首次运行时不能还原完整历史。软件不知道某个时间时会显示未知，不把目录修改时间或本次扫描时间当成最近打开时间。

## 2. 首次使用流程

1. 启动 DeskTrace，阅读当前版本支持的记录范围；安装包仍待发布。
2. 确认观察范围。首次启动已自动加入你的系统桌面，桌面上的每个文件和文件夹都会列出；需要时再添加其他文件夹，也可以停用桌面这一项。
3. 查看应用清单与日期来源，无法确定使用入口的应用会显示无法判断。
4. 启用记录；需要持续使用时，可以在设置中主动开启开机启动。
5. 经过足够观察时间后，按默认 90 天或自定义阈值查看候选。

不包含子目录时（桌面默认如此），范围里的每个文件和文件夹各算一项，打开某个文件夹里的任何内容都算用过这个文件夹。包含子目录时，浏览到的每个子目录各自成为一项。程序不会扫描整盘。

桌面文件是否被打开，依靠 Windows 的“最近使用的项目”。如果你在“设置 > 个性化 > 开始”里关闭了“在开始、跳转列表和文件资源管理器中显示最近打开的项目”，文件的打开就记录不到，DeskTrace 会把这些文件显示为“无法判断”并提示开启方法。程序、快捷方式和安装包的打开本来就不会被登记，它们会列出但不参与判断。

## 3. 如何理解时间

| 列表字段 | 含义 |
| --- | --- |
| 最近使用 | 本工具最近观察到应用进入前台或处于活跃使用 |
| 最近浏览 | 本工具最近观察到文件夹位于资源管理器活动视图 |
| 安装/更新日期 | 系统登记的应用安装、维护或包更新时间，详情说明来源 |
| 首次发现 | DeskTrace 第一次发现对象，不一定是安装时间 |
| 开始观察 | 当前这段观察的起点，用来判断是否观察足够久 |

日期只精确到天时只显示日期。应用后台运行、自动更新或托盘常驻不会直接视为你使用了应用。

文件夹只覆盖受支持的资源管理器浏览方式。IDE 内打开项目、第三方文件管理器或网络盘访问可能没有记录，不能据此认定完全未用。

## 4. 如何理解候选

- **近期有使用记录**：阈值以内观察到了使用。
- **较久未记录到使用**：观察时间足够，最后一条直接记录较旧，值得核对。
- **观察期内未记录到使用**：观察时间足够，但本工具没有直接记录；不能解释为历史上从未打开。
- **观察时间不足**：刚开始记录，尚不足以支持当前阈值。
- **无法判断**：身份、来源或观察信息不足。
- **已排除/已失联/暂不可访问**：分别说明你已停止观察、对象不再存在或当前无法访问。

“记录连续”仅表示支持范围内没有检测到缺口。“存在记录中断”或“覆盖未知”时，参考价值更有限；可用筛选仅查看连续记录。

不要仅凭候选状态决定删除。先核对内容或应用用途，再在资源管理器或 Windows 设置中整理。首期工具不自动删除，也不直接卸载应用。

## 5. 常用操作

搜索名称或路径，按最近时间和系统日期排序；无时间对象单独排在后面。查看详情可以了解来源、日期变化和采集缺口。

对经常不用但必须保留的工具或目录，可加入排除。目录排除可以包含子目录。恢复观察后重新计算观察起点，旧数据仍可查看，但不会当成完整的新观察期。

“打开位置”通过 Windows 打开已验证的对象位置；应用没有明确入口时提示无法定位。“应用管理”进入 Windows 应用设置，由你自行选择操作。

## 6. 记录、托盘与开机启动

关闭主窗口后，程序留在托盘继续记录。托盘可暂停、恢复或明确退出。退出、暂停和系统故障都会造成记录中断。

开机启动默认关闭。电脑锁屏或休眠期间不刷新活跃时间；长时间无输入也停止活跃采样。观看视频等无输入场景可能只有较早的前台记录。

## 7. 导出与数据清除

导出包含当前筛选的全部匹配结果。确认字段后选择保存位置；文件含名称、路径、时间与状态，分享前自行核对私人信息。

本地数据放在 `%LOCALAPPDATA%\DeskTrace\`。使用记录保存在你的电脑，不默认上传。默认原始事件保留 180 天，最近时间和必要区间保留到你清除。

在设置中点击“清除本工具记录…”，先查看影响对象数，确认后才清除。确认超过 60 秒或期间数据变化时需要重新发起。清除的是 DeskTrace 使用记录和观察区间，保留清单、设置、观察范围和排除规则；恢复采集后重新开始观察。不会删除实际文件夹、其他应用或 Windows 自身历史。

安装包尚未提供，卸载保留数据的策略待发布阶段验收。普通日志默认不含完整路径或窗口标题。

## 8. 常见问题

**安装日期为什么和记忆不同？** 系统日期可能在更新或修复后变化，详情会说明含义；原始安装时间可能无法获取。

**刚安装 DeskTrace 就能找出所有半年没用的内容吗？** 不能。系统历史不保证完整，首期主要依赖启用后的观察。旧安装日期只能提供核对线索。

**应用明明用过，为什么无法判断？** 可能是使用发生在本工具启用前、记录中断、权限受限或入口尚不支持。先查看详情，不把未知当成未用。

**没有进入前台的应用会记录吗？** 首期以可观察的用户前台使用为准，后台任务不会仅因运行而刷新。

**外置盘断开后，文件夹会被当成长期没用吗？** 会显示暂不可访问或已失联，先确认盘是否连接，再判断内容用途。
