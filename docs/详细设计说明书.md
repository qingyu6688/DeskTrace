# 详细设计说明书

版本：`0.5.0`。日期：2026-10-11。状态：后端已按本文实现；资源管理器多标签页识别与桌面文件打开记录仍须按测试计划实机验证。

## 1. 采集线程与生命周期

前台事件使用专用消息循环线程。回调只复制必要的窗口/进程引用并入队，不调用数据库、不解析文件夹、不执行长任务。入队前检查当前运行状态和会话。

COM 使用独立 STA 工作线程，初始化和释放均在所属线程完成，不跨线程共享未封送接口。Explorer 调用卡顿不能堵塞应用采集或 UI；调用耗时异常后停止继续派发、标记故障并退避，不宣称能强制取消正在阻塞的 COM 调用。若原型发现长期挂死，再评估隔离辅助进程。

有界事件队列容量初设 4096，待压测调整。达到上限时汇总丢失数量并形成缺口，不静默丢弃后仍声称覆盖连续。数据库工作线程统一串行写入；批次最多 100 条或等待 1 秒，以先到者提交。数值放入具名配置常量。

### 1.1 事件去重键

首版采用一分钟聚合，目的为幂等写入和最近时间维护，不用于统计精确打开次数。`dedup_key` 由核心库统一生成，采集器和前端不能自行拼接：

```text
v1:{object_id}:{event_kind}:{observation_generation}:{source}:{utc_minute_bucket}
utc_minute_bucket = observed_at_ms / 60000（非负整数除法）
```

`object_id` 使用 UUID 标准小写连字符形式；代次为正整数；`observed_at_ms` 为事件发生时的 UTC Unix 毫秒，不能改成入库/重试时刻。事件类型和来源均为固定枚举，来源从类型导出：

| event_kind | source |
| --- | --- |
| `app_foreground` | `foreground_hook` |
| `app_active_sample` | `foreground_sample` |
| `folder_browsed` | `explorer_shell` |
| `folder_visible_sample` | `explorer_shell` |

示例：对象 `00000000-0000-0000-0000-000000000001`，类型 `app_foreground`，代次 1，观察时间 `120001` 毫秒，得到 `v1:00000000-0000-0000-0000-000000000001:app_foreground:1:foreground_hook:2`。

同一对象、类型、代次与来源在同一 UTC 分钟只占一行。该分钟内两次真实前台激活也会合并；不同分钟、事件类型、对象或代次不合并。进程/窗口 ID 不进入键，避免同一应用的多窗口重复和 PID 重用；对象匹配必须先完成。重试沿用原事件时间和代次，不能跨分钟重新生成时间。

唯一键冲突采用 UPSERT：保留原行 ID 和首次创建时间，`observed_at` 取新旧最大值；对象 `last_used_at` 同一事务取最大值。较晚事件合并后仍推进最近时间，较早重试不倒退；不能简单 `INSERT OR IGNORE` 后跳过聚合。旧代次、未来时间、对象类型与事件不符的输入在 UPSERT 前拒绝。该规则验证“一分钟聚合行不重复”，不声称“所有真实动作只发生一次”。

## 2. 应用使用记录

1. 接收前台窗口事件，忽略本工具、无有效窗口和不支持的系统界面。
2. 确认当前用户会话未锁定，提取窗口所属进程，使用最小查询权限读取身份。
3. 优先解析包身份；普通应用读取可执行路径。PID 与进程创建时间共同校验，防止 PID 重用。
4. 与已验证入口匹配；无法归属时建立独立的可观察入口，不按相似名称合并安装项。
5. 写 `app_foreground` 直接观察事件，更新 `last_used_at`。
6. 每 60 秒校验仍在前台、会话未锁定且空闲不足 300 秒时，写 `app_active_sample`，刷新最近使用；采样不是精确启动记录。

空闲只查询最后输入发生时间，不监听具体按键。最后输入计数存在回绕或异常时按未知处理，不能将负差值误判为活跃。播放视频但长时间无输入等场景可能停止采样，属于首期口径限制。进程在后台运行、自动更新、服务启动和窗口最小化不刷新最近使用。

UWP/MSIX 使用进程包身份与具体应用入口关联；只拿到包而无法区分入口时，保留包级未解析对象，不能把同包所有应用同时算作使用。共享宿主、终端宿主和启动器按实际支持矩阵处理。

## 3. 文件夹浏览记录

仅在 Explorer 处于前台且用户会话活跃时，每 2 秒检查活动 Shell view 的文件系统项目。前台事件可触发一次即时检查，计时器用于同一窗口内的导航与标签切换。

适配器返回实际活动路径和可用文件标识。只对已加入范围的本地目录记录 `folder_browsed`；范围包含子目录时，浏览到的子目录按需建立对象，不提前遍历全部目录。

对象变化、窗口重新获得前台或采集恢复时形成一次浏览观察。同一目录持续可见且用户活跃时，每 60 秒最多写一次 `folder_visible_sample`，更新最近浏览，避免一个长期停留的目录被误判陈旧。这些时间表示观察到浏览/可见，不声称还原真正打开动作。

不能确定活动标签页时返回 `unsupported_view`，不使用窗口标题、后台标签路径或所有 Shell 窗口最大值猜测。系统虚拟项目、搜索结果、网络盘和不在范围的目录不进入长期判断。

极短导航可能在 2 秒间隔内漏记；原型测量漏记率，详情说明采样性质。目录一直后台打开不构成用户前台浏览。

## 4. 身份与路径

目录优先用卷标识和文件 ID 建立身份，另存路径。ID 不可读时使用原生解析得到的规范绝对路径，注明路径身份；不要仅用目录名合并。

路径比较按 Windows 原生规则处理，识别区分大小写目录，不能只依赖 SQLite `NOCASE` 或通用转小写。去除冗余分隔符和 `.`，保留正确根目录与长路径。子树匹配按路径组件，`C:\Work` 不能匹配 `C:\Workshop`。

排除检查包含原始路径与可解析的最终目标，防止符号链接绕过排除。首期不自动遍历重解析点。移动/重命名只有相同卷与文件 ID 等可靠证据时延续记录；跨卷移动和路径复用不自动继承。

应用入口匹配优先：已验证 AUMID/包应用入口、人工确认入口、可执行文件稳定身份与规范路径。卸载项 ID 是清单身份，不保证直接提供启动入口。安装目录前缀只能提出匹配建议，不能独立证明某个进程属于该安装项。

## 5. 安装清单与日期

读取 `HKCU` 和 `HKLM` 中的 `Software\Microsoft\Windows\CurrentVersion\Uninstall`，显式指定 32/64 位注册表视图并去重。当前用户 MSIX 使用 `FindPackagesForUser` 的当前用户形式，过滤框架、资源包等无用户入口的项。

只保存所需名称、发布者、版本、身份线索与日期，不执行 `UninstallString`，不扫描其他用户配置。清单首次启动读取，此后每 6 小时或用户手动刷新。任务可取消；一次读取失败不等于应用被卸载。

`InstallDate` 优先严格解析合法 `yyyyMMdd`，其他格式仅按明确的提供方规则处理。MSI 标为“安装/维护日期”，无法确认提供方语义的值标为“系统登记日期”。MSIX 标为“包安装/更新日期”。原始值和本次读取时间进入日期证据表。

只有日期的值保存 `date` 与 `day` 精度，不能转换为假精确时间。缺失、非法或未来值标未知并保留诊断原因；不回填目录时间。首次发现只表示本工具发现，不能称为安装。

同一来源的新日期形成新快照。连续相同值不重复存；来源日期最早值也不能据此认定原始安装时间。完整扫描连续两次确认对象不存在，才标记清单失联；扫描部分失败时不执行这一步。

## 6. 长期候选算法

输入：对象、直接记录 `last_used_at`、当前 `observation_started_at`、身份/来源可用性、排除规则、采集区间、阈值和当前时间。

`cutoff = now - threshold_days × 86400 秒`，边界等于截止时刻算近期。算法按顺序执行：

1. 匹配排除规则，返回 `excluded`。
2. 对象确认失联或不可访问，返回 `unavailable` 并说明具体原因。
3. 无可观察身份/来源或没有有效观察起点，返回 `unknown`。
4. 有可信直接记录且 `last_used_at >= cutoff`，返回 `recent`。
5. `observation_started_at > cutoff`，返回 `insufficient_observation`。
6. 直接记录为空，返回 `never_observed`；否则返回 `stale_candidate`。

最后两类附带区间覆盖和来源限制；不能简写为“从未打开”。启用前的安装日期和后续历史线索都不参加该算法。未来时间戳、时钟异常或本代次新事件早于合法观察起点时，先标为异常，返回无法判断，不直接计算候选。恢复观察时保留的旧代次合法历史可以早于新起点，不因此视为异常；其时间仍可展示，连续覆盖只从新起点计算。

`continuous` 只表示在声明支持范围内没有检测到记录缺口。`partial` 表示存在已知暂停或故障；`unknown` 表示有未验证区间。阈值跨度足够但覆盖不足的对象仍可以列为线索，默认附醒目标识；“仅连续记录”筛选只保留 `continuous`。

示例均以 2026-10-11 查询、阈值 90 天为条件：

| 情况 | 结果 |
| --- | --- |
| 开始观察只有 10 天，从未记录 | 观察时间不足，不能按安装龄判候选 |
| 已观察 120 天，最近使用 100 天前，来源连续 | 较久未记录到使用，注明 90 天阈值 |
| 已观察 120 天，无直接记录，中间暂停 30 天 | 观察期内未记录，注明存在记录中断 |
| 安装 3 年，入口无法匹配 | 无法判断 |
| 近期前台使用，但应用仍有旧安装日期 | 近期有使用记录 |

## 7. 区间与时钟

按 `applications/folders` 两个模块保存区间，不用一条全局状态掩盖局部失败。启用、暂停、锁屏、休眠、故障与恢复均结束旧区间并开始新状态。

### 7.1 状态与原因枚举

`reason` 为受约束的机器枚举，不是自由文本；中文说明由显示层转换。每个原因只有一个合法状态，核心库和数据库同时约束：

| reason | interval_state | 场景与覆盖解释 |
| --- | --- | --- |
| `collection_started` | `active` | 用户首次启用，模块就绪 |
| `collection_resumed` | `active` | 用户恢复、解锁或休眠返回且模块就绪 |
| `collector_recovered` | `active` | 故障恢复且健康检查成功 |
| `session_locked` | `inactive` | 确认当前会话锁定，不发生本口径的前台使用 |
| `system_suspended` | `inactive` | 有明确休眠/恢复证据 |
| `user_idle` | `inactive` | 来源健康、会话空闲达到阈值，停止活跃采样 |
| `user_paused` | `gap` | 用户暂停，期间可能使用电脑 |
| `collector_fault` | `gap` | 模块异常或 COM 卡顿，已知无法正常采集 |
| `permission_denied` | `gap` | 所需来源无法查询；相关模块覆盖受损 |
| `unsupported_view` | `gap` | 前台 Explorer 活动视图无法可靠解析，仅影响文件夹模块 |
| `queue_overflow` | `gap` | 相关模块事件已丢失 |
| `storage_error` | `gap` | 有观察但无法持久化 |
| `source_disabled` | `gap` | 系统关闭了所需来源（“显示最近打开的项目”），仅影响文件模块 |
| `startup_unverified` | `unknown` | 启动前区间没有足够证据 |
| `unexpected_exit` | `unknown` | 最后有效心跳到重启之间无法验证 |
| `collector_stopped` | `unknown` | 明确退出后无法知道用户是否继续使用电脑 |
| `clock_change` | `unknown` | 墙上时间异常，无法可靠定位覆盖区间 |

`inactive` 可以作为本产品前台活跃口径下的可解释非活跃区间，不能扩展为“后台没有运行”。`gap` 是已知漏记，导致 partial；`unknown` 导致 unknown，优先于 partial。连续性只有在整个查询窗口由 active 和有证据的 inactive 区间组成时成立。

发生多个原因时保留全部诊断，但当前区间选一个主因：时钟异常优先，其次存储/队列/采集故障，其次用户暂停，再到已确认锁屏/休眠/空闲，最后正常采集。模块健康有问题时不能仅因空闲而记为 inactive；恢复操作只有在健康检查通过后才转 active。

状态和原因切换在一个事务中关闭旧区间、建立新区间，转换时刻相同。同状态同原因只推进心跳，不重复建立区间；同状态不同原因也要拆分。数据库故障时无法即时写入缺口，先保留待补写状态，恢复后补齐；期间进程退出则依最后心跳生成 unknown，不能声称故障记录已可靠落盘。

每 15 秒提交采集健康心跳，`verified_until` 只推进到已确认的采集时刻。启动发现未关闭区间时，保留最后心跳至本次启动的未知缺口。确认锁屏/休眠的区间标为非活跃，不能延伸成用户使用；缺失恢复信号按未知处理。关闭本工具后的离线区间默认未知，不猜测期间电脑是否关机。

只在查询覆盖窗口内的每一段时间都有可解释证据、模块无故障且来源支持对象时，给出 `continuous`。排除、移出范围或清除记录会结束当前观察；恢复时建立新观察起点。

事件墙上时间用 UTC；间隔用单调时钟。墙上时间与单调时间变化偏差超过初设 5 分钟时标记 `clock_change`，受影响区间无法参与连续性结论。系统时区改变只影响显示，不改变已存时间。

## 8. 排除、保留与清除

排除先作用于采集入口和列表判断，再作用于写入；后台队列中的已排除事件也要过滤。目录子树排除保存为显式规则。默认保留旧记录但停止后续记录，用户可另行清除。

清除本工具使用数据时先暂停采集、递增记录代次、排空旧代次事件，再以事务清除事件、最近时间与采集区间；保留观察范围和排除设置，重新开始观察。身份未清除不意味着继续使用旧观察起点。清除不操作系统 Recent 或用户实际文件。

默认 180 天后删除原始使用事件，保留经过事务维护的最近直接时间和压缩区间，避免 365 天阈值因为事件已裁剪而失真。日期快照去重，必要证据保留；日志默认保留 7 天。

## 9. 导出与用户操作

CSV 导出是当前筛选的全部匹配结果，不仅当前页。字段包括对象类型、名称、路径或入口、最近观察时间、系统日期及含义、观察起点、候选和覆盖。时间用带偏移的 ISO 8601，日期级值保持日期。

UTF-8 BOM、标准 CSV 引号转义；文本以 `= + - @` 或制表符等潜在公式前缀开头时进行安全文本处理。导出目的地来自原生保存对话框凭据，不接受前端任意写入路径；后台分页写出，支持取消和临时文件回滚。

打开目录按对象 ID 查询已校验路径，通过系统 API 执行，不拼接 Shell 字符串。应用卸载入口只打开 Windows 应用设置，不直接执行注册表卸载命令。动作请求不刷新使用时间，采集确认才刷新。

## 10. 实现说明（0.4.0）

以下是落地时补充的具体规则，代码与本节保持一致。

**前台与空闲。** 前台切换和目录浏览在写入前重新读取最后输入时间，空闲达到 300 秒时只更新当前对象、不写事件。计划任务或安装程序在用户离开时抢走焦点，不会被记成使用；用户真正点击切换时输入计时会立即清零。空闲期间未写入的对象，在用户恢复操作后的第一次检查立即补一条活跃采样。

**心跳与覆盖。** 心跳每 15 秒推进，容差 45 秒。距上次心跳超过容差（进程被系统挂起等）时，关闭旧区间并以相同原因重开，中间留下空档。覆盖计算中，已关闭的采集与非活跃区间只认到 `verified_until`；暂停、故障、未知等缺口区间是对整段时间的声明，按 `ended_at`（进行中按当前时刻）。没有任何区间证据的空档按未知，详情轨迹以 `unverified` 列出。

**启动与退出。** 启动时先处理遗留的开放区间：正常退出留下的“程序已退出”关闭到当前时刻；其他区间关闭到最后心跳，之后补一段 `unexpected_exit`。首次同步区间前先读空闲状态，避免零长度区间。托盘“退出”和进程正常结束都会把两个模块切换为 `collector_stopped`。

**应用归属。** Win32 清单项的主程序只取 `DisplayIcon` 指向的、真实存在的 `.exe`，排除文件名以 `unins`、`setup` 开头或包含 `uninstall`、`installer` 的程序，以及 `msiexec`、`update`、`updater`；取不到时清单项保持“无法匹配入口”。前台遇到未登记的可执行文件时建立便携应用对象；同一可执行文件已归属其他对象时不自动合并。`ApplicationFrameHost.exe` 承载的窗口改用子窗口所属进程的包身份；锁屏、开始菜单、搜索、输入法面板等系统界面进程不计入。

**资源管理器活动标签页。** 取前台 `CabinetWClass` 窗口下第一个 `ShellTabWindowClass` 子窗口，在 `IShellWindows` 中找 `IShellBrowser::GetWindow` 与之相同的一项，再从活动视图读取文件系统路径。没有标签页子窗口时，同一顶层窗口只有一个浏览器才采用。任何一步对不上返回 `unsupported_view`；此电脑、搜索结果等返回虚拟位置，不记录也不算缺口。单次探测超过 2 秒视为卡顿，标记采集故障并退避 30 秒。

**目录可访问性。** 每 10 分钟检查一次目录对象：盘符根不存在为暂不可访问，盘符在但目录不在为已失联，重新出现后恢复可用。新增观察范围时立即为范围根目录建立对象，从未浏览过的根目录也能在观察期满后成为“观察期内未记录”。

**时钟。** 墙上时间相对单调时钟倒退超过 5 分钟，或在休眠恢复 2 分钟以外前跳超过 5 分钟，记 1 秒以上的 `clock_change` 区间。按本地日期汇总轨迹时，存储层按 15 分钟 UTC 桶取数，每个桶按其时刻的系统时区偏移换算，夏令时切换日也不会错位。

**清除记录。** 清除后区间表为空，采集线程重新建立区间；采集线程缓存的旧代次对象在下一次写入时被拒绝并重新登记。

## 11. 桌面文件与观察范围（0.5.0）

**默认范围。** 首次启动读取当前用户的系统桌面（已知文件夹，OneDrive 或组策略重定向后取实际位置），以“不包含子目录”加入观察范围，并写一次性标记。用户删除桌面范围后不会被自动加回，可在设置中一键重新加入。用户仍可添加多个其他目录。

**范围归属。** 路径等于范围根时记到根；范围包含子目录时记到路径本身；不包含子目录时记到范围根下的直接子项。例如桌面上“旧资料”文件夹里任意深处的浏览或打开，都记到“旧资料”。多个范围同时命中时取根路径最长的一个。

**直接子项登记。** 启动后第一次定时检查、范围增删改之后和每 10 分钟，列出每个启用范围根目录的直接子项，登记为文件或文件夹对象。隐藏和系统项（如 `desktop.ini`）、符号链接和目录联接不登记。只为新出现的路径读取文件 ID；文件 ID 相同而路径变化时视为同卷重命名，延续同一对象。消失的子项由可访问性检查标为已失联。

**文件打开来源。** 程序运行期间监听当前用户的“最近使用的项目”目录：新增、修改或改名后的快捷方式被解析出目标路径，按范围归属记录。目标是范围内文件时写 `file_opened`；目标是目录或更深处的内容时，在所属目录对象上写 `folder_content_opened`。与前台切换一样，用户空闲时不记录。启用前留在该目录里的历史不读取。

**记录不到的情况。** 程序、脚本、安装包和快捷方式（`exe`、`bat`、`msi`、`lnk`、`url` 等）打开时不会登记到“最近使用的项目”，这类文件只列出、状态为“这类文件的打开无法记录”，不会被判为长期未用。系统设置关闭“显示最近打开的项目”或组策略 `NoRecentDocsHistory` 生效时，文件模块记 `source_disabled` 缺口，可观察文件的“较久未记录 / 未记录 / 观察不足”改为“无法判断”并说明原因；界面提供进入“设置 > 个性化 > 开始”的入口，程序不修改该设置。开关每 30 秒检查一次。不登记最近文档的软件打开的文件同样记录不到，属于首期口径限制。

**模块划分。** 文件打开单独作为 `files` 模块保存区间，与资源管理器浏览的 `folders` 模块互不影响。
