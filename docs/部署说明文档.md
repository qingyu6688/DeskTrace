# 部署说明文档

版本：`0.6.0`。日期：2026-10-11。状态：前后端已联通，可构建桌面程序，分发安装包仍待实施。

## 1. 部署形态

Windows 11 x64 用户级桌面安装包，初选 Tauri NSIS。应用默认以普通用户运行，数据保存在当前用户本地目录。无 Nginx、Docker、Java 服务、MySQL 依赖或生产 HTTP 端口。

MSI 暂不作为首期打包目标，后续需要时单独验证其构建前提。安装包大小、运行内存和安装成功率均待实测。

## 2. 开发前提

- Rust stable 的 MSVC 工具链。
- Microsoft C++ Build Tools 与 Windows SDK。
- Node.js、pnpm 和可运行的 WebView2 Runtime。
- Windows 11 实机或测试环境，用于原生采集验证。

本机版本见环境检查记录。首次编译验证链接器与 SDK 后再锁定工程版本；本次没有安装、升级或修改这些工具。

参考：[Tauri 开发前提](https://v2.tauri.app/start/prerequisites/)、[WebView2 分发](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。

## 3. 工程命令

开发模式连接真实本地数据库。启动时读取应用清单；用户启用记录后开始采集前台应用和资源管理器浏览。关闭主窗口只隐藏到托盘，托盘菜单可打开窗口、暂停/恢复记录或退出；带 `--autostart` 参数启动时不弹出主窗口，开机启动项写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。同一用户只运行一个实例，再次启动会唤起已有窗口。

调试构建认 `DESKTRACE_DATA_DIR`（必须是绝对路径）作为数据目录，便于测试时不碰真实数据；发布构建忽略该变量。

`frontend/package.json` 的 `dev` 为 Vite、`build` 为类型检查和前端生产构建、`test` 为 Vitest 单次运行、`lint` 为 ESLint。`tauri` 脚本先切换至 `backend/src-tauri/` 再调用前端安装的 Tauri CLI；后端配置显式指定前端工作目录和资产位置。

在项目根目录 `F:\桌面\DeskTrace` 的 PowerShell 执行：

```powershell
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend tauri dev
```

首次建立依赖清单时生成锁文件；已有锁文件后的安装使用 `--frozen-lockfile`。开发服务器绑定 `127.0.0.1:1420`，需要 HMR 时固定为 1421；配置端口严格检查，冲突时提示，不静默切换。

单独预览前端执行 `pnpm --dir frontend dev`，访问 `http://127.0.0.1:1420/`。与 Tauri 开发模式共用端口，切换启动方式前停止已有 Vite 服务。浏览器保持空清单并提示未连接，原生操作禁用；桌面模式使用真实 IPC 和持久化数据，详见 [前端实现说明](前端实现说明.md)。

提交前验证顺序：

```powershell
Set-Location F:\桌面\DeskTrace\frontend
pnpm test
pnpm build
pnpm lint
Set-Location ..\backend
cargo test --workspace --locked
cargo build --workspace --locked
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
```

在项目根目录构建桌面可执行文件，暂不生成安装包：

```powershell
pnpm --dir frontend tauri build --no-bundle
```

正式构建产物位于 `backend\target\release\desktrace-desktop.exe`；加 `--debug` 的开发构建位于 `backend\target\debug\desktrace-desktop.exe`。前端产物位于 `frontend/dist/`，SQLite 迁移源码位于 `backend/migrations/`。当前 `bundle.active=false`；NSIS 正式打包参数、图标、签名、运行时和安装/升级行为需发布阶段再验证。完成构建不等于安装包发布通过。

移动工程目录后，Node 依赖元数据与 Tauri 构建缓存可能保留旧绝对路径。前端在新目录重新执行锁定安装；如是无终端的自动化环境，单次设置 `CI=true` 后安装。后端在 `backend/` 执行 `cargo clean -p tauri` 再构建，可重新生成权限路径。以上仅重建项目依赖与编译缓存，迁移文件内容不需要修改。

## 4. 文件与日志

| 内容 | 计划位置 | 要求 |
| --- | --- | --- |
| 应用文件 | `%LOCALAPPDATA%\Programs\DeskTrace\` | 安装目录与数据分开 |
| 用户数据根目录 | `%LOCALAPPDATA%\DeskTrace\` | 通过系统 API 定位，不能硬编码用户名 |
| 数据库 | 数据根目录下 `desktrace.sqlite3` | 只使用本地可写磁盘 |
| WAL/共享内存 | 数据库旁的 `-wal`、`-shm` 文件 | 运行中由 SQLite 管理 |
| 备份 | 数据根目录下 `backups\` | 已有数据升级结构前用 `VACUUM INTO` 生成一致快照，文件名含原版本号与时间 |
| 日志 | 数据根目录下 `logs\` | 默认保留 7 天，屏蔽路径、窗口标题和原始日期载荷 |

正式包不用 `.env` 保存运行设置。当前无外部凭据；后续新增 `.env` 时先加入 `.gitignore`，文档只写变量名和示例占位。开发专用数据目录不得用于生产包任意路径覆盖。

## 5. 权限与发布配置

显式列出可信本地窗口和自定义命令权限；只加载打包资产。不开启生产调试入口，不暴露原始堆栈，不注册默认联网遥测或自动更新。

目录选择、导出与清除使用原生对话框和后端校验。开机启动只配置当前用户，默认关闭。用户关闭主窗口前知道应用继续在托盘记录，明确退出立即停止。

签名凭据不进入仓库、文档或日志。对外分发前决定代码签名和 WebView2 缺失时的安装策略；需要联网补装时给出明确说明，离线环境准备受支持的运行时分发方式。

## 6. 升级与恢复

1. 升级前关闭运行实例，安装程序替换应用文件，保留用户数据库。
2. 新版本启动校验迁移版本和校验和，使用数据库备份接口创建一致备份。
3. 迁移成功再开始采集；失败保持原文件和备份，不带病启动。
4. 恢复时停止所有进程与连接，校验备份，在受控流程中替换数据库；恢复后按备份时刻标记后续记录缺口。

不能在 WAL 活跃时只复制主文件备份。未经兼容性确认，旧版本不能打开已升级结构；回滚要用对应备份，不能盲目倒换二进制。

卸载移除应用和开机启动项，默认保留用户记录。用户若需删除记录，在本工具明确清除或卸载流程中选择；不连带操作真实文件夹和其他应用。
