# 接口设计文档

版本：`0.6.0`。日期：2026-10-11。状态：全部命令已在后端实现，前端已接入业务命令与三个刷新事件。

## 1. 接口形态

前端通过 `frontend/src/api/` 中的类型化封装调用 Rust 命令，不直接访问数据库、注册表或系统文件。首期没有 HTTP 服务，所以无 REST 路径、鉴权 Token 或数据库端口。

IPC 使用 `camelCase` DTO 字段，Rust 与数据库按各自语言约定命名。命令名称使用英文 `snake_case`。公共类型集中在 `frontend/src/types/`，不使用任意 `any`。

前端请求统一通过 `src/api/` 封装，业务 DTO 定义于 `src/types/ipc.ts`；候选状态、说明、轨迹和区间覆盖直接采用 Rust 返回。浏览器未连接时不回退到样本。具体命令入口、刷新与确认流程见 [前端实现说明](前端实现说明.md)。

## 2. 通用返回

```typescript
type ApiResponse<T> =
  | { code: 200; message: string; data: T }
  | { code: 400 | 403 | 404 | 409 | 422 | 500 | 503; message: string; data: null };

interface PageResult<T> {
  items: T[];
  total: number;
  page: number;
  pageSize: number;
}

type CandidateStatus =
  | 'recent'
  | 'stale_candidate'
  | 'never_observed'
  | 'insufficient_observation'
  | 'unknown'
  | 'excluded'
  | 'unavailable';

type CoverageStatus = 'continuous' | 'partial' | 'unknown';

interface ObjectSummary {
  id: string;
  objectType: 'folder' | 'application' | 'file';
  displayName: string;
  currentPath: string | null;
  firstSeenAt: string;
  observationStartedAt: string | null;
  lastUsedAt: string | null;
  candidateStatus: CandidateStatus;
  coverageStatus: CoverageStatus;
  statusReason: string;
  installationDate: string | null;
  installationPrecision: 'day' | 'instant' | 'unknown';
  installationMeaning: 'install_or_service' | 'install_or_update' | 'registered' | 'unknown';
  installationSource: 'uninstall_registry' | 'package_api' | null;
  installationValidation: 'valid' | 'missing' | 'invalid' | 'future' | null;
  remainingObservationDays: number | null;
  publisher: string | null;
  displayVersion: string | null;
  applicationKind: 'win32' | 'msix' | 'portable' | 'unresolved' | null;
  exclusion: { ruleId: string; mode: 'object' | 'folder_tree' } | null;
}
```

`remainingObservationDays` 只在观察不足时有值；`installationValidation` 用来区分“登记里没有日期”和“日期格式非法”；`exclusion` 给出命中的排除规则，子树排除时可能指向父目录的规则。

时间级字段使用 UTC RFC 3339 字符串，日期级安装值使用 `YYYY-MM-DD`。文件夹安装字段为空。`statusReason` 为可展示的中文说明，不包含原始堆栈。

成功示例：

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "pageSize": 50
  }
}
```

业务错误通过统一结构返回；传输级异常在 `frontend/src/api/` 中转换为中文提示并保留脱敏诊断。禁止前端忽略非 200 状态继续使用旧数据冒充新查询结果。

## 3. 命令清单

`get_bootstrap_status`：无参数，返回版本、当前平台支持标记、采集实现标记、本地数据库结构版本/对象与事件计数/数据目录、60 秒聚合窗口和 17 个原因数量；数据库线程失败返回 503。

参数列是 `invoke` 的第二个参数，键名按 `camelCase` 传入。所有命令只允许主窗口调用，见 `backend/src-tauri/capabilities/main.json`。

| 命令 | 参数 | 成功数据 | 行为 |
| --- | --- | --- | --- |
| `get_overview` | `{ thresholdDays }` | `Overview` | 两类对象在同一阈值下的七种状态计数、最早开始记录时刻、最近 20 条缺口与观察范围 |
| `list_objects` | `{ query: ObjectQuery }` | `PageResult<ObjectSummary>` | 搜索、筛选、排序和分页 |
| `get_object_detail` | `{ objectId, thresholdDays? }` | `ObjectDetail` | 阈值缺省用设置值；事件最近 100 条、日期证据最近 20 条；轨迹见第 4 节 |
| `list_object_events` | `{ objectId, page, pageSize }` | 分页事件 | 不一次加载全部历史 |
| `refresh_application_catalog` | 无 | `{ jobId }` | 异步刷新应用清单，已有任务时复用任务 ID |
| `get_collector_status` | 无 | `CollectorStatus` | 应用与文件夹分别报告区间状态、健康与心跳，附清单刷新情况和已知限制 |
| `set_collection_state` | `{ state: 'running' 或 'paused' }` | `CollectorStatus` | 幂等；已启用过的记录不能回到“尚未启用”；首次启用由界面先完成引导 |
| `pick_folder_scope` | 无 | `{ path, selectionToken }`，取消为 `null` | 原生选择对话框；网络路径返回 422 |
| `add_desktop_scope` | 无 | 范围对象 | 把当前用户的系统桌面加入范围（不包含子目录）；已存在返回 409，读不到桌面位置返回 503 |
| `add_folder_scope` | `{ selectionToken, includeDescendants }` | 范围对象 | 后端解析凭据并检查路径 |
| `list_folder_scopes` | 无 | 范围列表 | 返回已配置路径与状态 |
| `update_folder_scope` | `{ scopeId, enabled, includeDescendants }` | 范围对象 | 重新计算对象可观察状态 |
| `remove_folder_scope` | `{ scopeId }` | `{ removed: true }` | 停止相关观察，保留既有历史 |
| `add_exclusion` | `{ objectId, mode: 'object' 或 'folder_tree' }` | 排除规则 | 子树模式只用于目录 |
| `list_exclusions` | 无 | 规则列表 | 展示排除内容 |
| `remove_exclusion` | `{ ruleId }` | `{ removed: true }` | 恢复范围内对象，重新开始观察 |
| `get_settings` | 无 | 类型化设置 | 无任意键查询 |
| `update_settings` | `{ patch: SettingsPatch }` | 完整设置 | 任一字段非法时整体不生效；开机启动写入失败返回 500，所有字段都不保存 |
| `open_object_location` | `{ objectId }` | `{ requested: true }` | 打开目录；文件和应用入口在资源管理器中定位选中，不直接打开 |
| `open_application_settings` | 无 | `{ requested: true }` | 进入 Windows 应用设置 |
| `open_recent_items_settings` | 无 | `{ requested: true }` | 进入“设置 > 个性化 > 开始”，由用户自己开启“显示最近打开的项目”；程序不修改该设置 |
| `request_export` | `{ query: ObjectQuery, confirmedFields }` | `{ jobId, cancelled }` | 原生保存对话框后后台导出全部匹配结果；取消时 `jobId` 为 `null`、`cancelled` 为真；同时只允许一个导出任务 |
| `get_job_status` | `{ jobId }` | `JobSnapshot` | 支持清单刷新与导出任务，保留最近 20 个已结束任务 |
| `cancel_job` | `{ jobId }` | 任务状态 | 取消只读扫描或导出，删除未完成临时输出 |
| `prepare_clear_usage_data` | 无 | `{ confirmationToken, affectedObjects, expiresInSeconds }` | 生成有时效、绑定当前数据代次的凭据 |
| `clear_usage_data` | `{ confirmationToken }` | `{ cleared: true }` | 暂停、清除本工具记录并重置观察 |

目录选择凭据只在当前进程使用、有效 60 秒、消费一次；失效返回 409。清除凭据有效 60 秒，必须来自用户看到影响说明后的确认，不接受任意布尔值绕过。

## 4. 查询与设置参数

```typescript
interface ObjectQuery {
  objectType: 'folder' | 'application' | 'file' | 'location';
  keyword?: string;
  candidateStatuses?: CandidateStatus[];
  coverageStatus?: CoverageStatus;
  thresholdDays: number;
  sortBy: 'displayName' | 'lastUsedAt' | 'firstSeenAt' | 'installationDate';
  sortDirection: 'asc' | 'desc';
  page: number;
  pageSize: number;
}

interface SettingsPatch {
  thresholdDays?: number;
  eventRetentionDays?: number;
  autoStartEnabled?: boolean;
}
```

`objectType` 为 `location` 时同时列出文件和文件夹，用于桌面页。`thresholdDays` 为 1～3650 整数，默认 90；保留天数 30～3650，默认 180；页码从 1 开始，页大小 1～200，默认 50；搜索词最长 200 个 Unicode 字符。未知字段与未知枚举值返回 400，不拼接排序 SQL。

列表 DTO 的安装日期来自后端按有效性和来源含义选取的当前证据，不能从首次发现时间计算。排序无法比较的未知值统一置后。

详情中的观察轨迹供界面绘制，画法见 [UI 设计说明](../UI/UI设计说明.md) 第 7 节：

```typescript
interface ObservationTrack {
  windowStart: string;
  windowEnd: string;
  usageDays: string[];
  lastUsedAt: string | null;
  gaps: TrackGap[];
}

interface TrackGap {
  module: 'applications' | 'folders' | 'files';
  state: 'gap' | 'unknown';
  reason: string;
  reasonLabel: string;
  startedAt: string;
  endedAt: string | null;
}
```

`windowStart` 取当前观察起点与原始事件保留边界中较晚者，`windowEnd` 为查询时刻；对象没有观察起点时 `track` 为 `null`。`usageDays` 是窗口内有直接记录的本地日期 `YYYY-MM-DD`，按查询时系统时区换算，升序去重，不表示次数或时长。`lastUsedAt` 可以早于 `windowStart`（原始事件已清理或属于旧代次）。`gaps` 只返回与窗口相交的 `gap`、`unknown` 区间，`inactive` 不返回；`reason` 为区间原因枚举值，`reasonLabel` 为中文说明，进行中的区间 `endedAt` 为 `null`。两段区间之间没有任何证据的空档（例如进程被挂起、心跳中断）以 `state: 'unknown'`、`reason: 'unverified'`、`reasonLabel: '未记录到采集状态'` 列出，与覆盖计算保持一致；`unverified` 不写入数据库。轨迹只用于展示，不参与候选计算。

### 4.1 其他返回结构

```typescript
interface Overview {
  thresholdDays: number;
  applications: { total: number; counts: Record<CandidateStatus, number> };
  folders: { total: number; counts: Record<CandidateStatus, number> };
  files: { total: number; counts: Record<CandidateStatus, number> };
  observationStartedAt: string | null;
  recentGaps: TrackGap[];
  scopes: FolderScope[];
}

interface ObjectDetail {
  summary: ObjectSummary;
  identifiers: { kind: string; value: string | null; quality: string; source: string }[];
  evidence: { source: string; rawValue: string | null; dateValue: string | null; precision: string; meaning: string; validation: string; observedAt: string }[];
  recentEvents: { observedAt: string; eventKind: string; label: string }[];
  track: ObservationTrack | null;
}

interface FolderScope { id: string; path: string; includeDescendants: boolean; enabled: boolean; isSystemDesktop: boolean }

interface ExclusionRule {
  id: string;
  mode: 'object' | 'folder_tree';
  objectId: string | null;
  label: string;
  objectType: 'folder' | 'application' | 'file';
}

interface CollectorStatus {
  collectionState: 'not_started' | 'running' | 'paused';
  implemented: boolean;
  modules: {
    module: 'applications' | 'folders' | 'files';
    state: 'active' | 'inactive' | 'gap' | 'unknown' | null;
    reason: string | null;
    reasonLabel: string | null;
    healthy: boolean;
    lastHeartbeatAt: string | null;
  }[];
  catalog: { lastRefreshedAt: string | null; complete: boolean | null; runningJobId: string | null };
  limitations: string[];
}

interface JobSnapshot {
  jobId: string;
  kind: 'catalog_refresh' | 'export';
  status: 'pending' | 'running' | 'completed' | 'failed' | 'cancelled';
  stage: string;
  processed: number;
  total: number | null;
  message: string | null;
  resultPath: string | null;
}
```

身份标识中的文件 ID 属于不透明值，`value` 为 `null`。`confirmedFields` 只能取 `objectType`、`displayName`、`path`、`lastUsedAt`、`installationDate`、`installationMeaning`、`observationStartedAt`、`candidateStatus`、`coverageStatus`，导出列按这个固定顺序排列。

## 5. 事件通知与任务状态

| 事件 | 数据 | 说明 |
| --- | --- | --- |
| `collector-status-changed` | `CollectorStatus` | 任一模块的区间原因变化时推送 |
| `objects-updated` | `{ objectTypes, dataVersion }` | 最多每秒一次，合并期间的变化；页面按需刷新 |
| `job-progress` | `JobSnapshot` | 有总量才返回总量，不伪造百分比 |

任务状态为 `pending/running/completed/failed/cancelled`。事件是刷新提示，权威状态仍通过命令读取；界面重开后可恢复。任务结果只返回用户确认的导出路径，不泄露完整系统清单到日志。

## 6. 错误与安全校验

| 码 | 含义 | 示例中文文案 |
| --- | --- | --- |
| `200` | 成功 | 查询成功 |
| `400` | 参数错误 | 阈值必须为 1～3650 天的整数 |
| `403` | 权限不足或能力受限 | 当前权限无法读取该对象 |
| `404` | 对象或任务不存在 | 该记录已不存在，请刷新列表 |
| `409` | 冲突、过期凭据或状态变化 | 数据状态已变化，请重新确认 |
| `422` | 参数形式合法但动作不适用 | 此对象没有可定位的应用入口 |
| `500` | 内部失败 | 保存失败，请查看本地诊断信息 |
| `503` | 数据源或存储暂不可用 | 文件夹记录暂不可用，已有记录仍可查看 |

这是应用错误码，不能当作真实 HTTP 状态。所有变更和路径操作均在 Rust 再校验。清除记录、配置开机启动、导出和原生系统操作限制在可信本地窗口命令权限中。
