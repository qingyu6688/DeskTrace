# UI 设计说明

版本：`0.2.0`。日期：2026-10-11。状态：采用方案 A（清单工作台），详情面板加入观察轨迹；目前是静态原型，前端还没有按这份说明实现。

## 1. 文件

| 文件 | 内容 |
| --- | --- |
| `applications.html` | 应用列表和右侧详情面板，详情里有观察轨迹 |
| `overview.html` | 概览：采集状态、候选分布、记录缺口、观察范围 |
| `styles.css` | 两个页面共用的样式和设计变量 |

用浏览器直接打开 HTML 即可，不依赖网络或在线字体。页面里的应用、数量和日期都是演示数据，按 2026-10-11、阈值 90 天、观察起点 06-02 推算，前后能对上，但不是实测结果。

## 2. 为什么选方案 A

评审时一共出了三套方案：A 清单工作台、B 观察时间轴、C 整理队列。最终选 A，理由是它和现有需求、接口最贴合，开发成本最低。B 的观察轨迹很直观，但放在列表的每一行里，会让列表查询变重，所以只把它放进详情面板。

界面遵循四条原则：

1. **以表格为主。** 用户要做的事是筛选、排序、逐条核对，表格最直接。
2. **结论旁边放依据。** 状态标签只给结论；打开详情，第一屏能看到一句话的解释、观察轨迹和各项时间。
3. **不知道就写未知。** 没有时间就显示“未记录”或“未知”，不留空白，也不填 0；排序时这些项一律排在最后。
4. **不替用户删东西。** 能做的操作只有打开所在位置、进入 Windows 应用设置和排除，不提供删除或卸载按钮。

## 3. 页面框架

- **顶栏**（高 52px）：左边是品牌，右边是采集状态（正在记录 / 已暂停 / 部分异常）、已观察天数和“暂停记录”按钮。暂停后，按钮变成“恢复记录”，状态点变灰。
- **左侧导航**（宽 196px）：概览、文件夹、应用、设置，后面带对象数量。底部显示观察起点，并提醒“关闭窗口后在托盘继续记录”。
- **内容区**：从上到下依次是页标题和说明、筛选栏、状态筛选、主体。
- **窗口尺寸**：默认 1280×800，最小 960×640。窗口宽度 ≥ 1260px（侧栏 196 + 内边距 48 + 表格最小 650 + 间距 16 + 详情 340）时，列表和详情左右并排，默认窗口即为并排；更窄时，详情改用右侧抽屉（宽 360px），不要把详情挤到列表下面。原型里的换行效果只是为了在窄屏下也能正常显示。

## 5. 设计变量

变量都定义在 `styles.css` 的 `:root` 里，变量名可以直接迁移到前端。

| 用途 | 变量 | 值 |
| --- | --- | --- |
| 页面背景 | `--color-bg` | `#f4f5f7` |
| 面板 | `--color-surface` | `#ffffff` |
| 边框 / 分隔线 | `--color-border` / `--color-divider` | `#e1e4e9` / `#eef0f3` |
| 正文 / 次要文字 | `--color-text` / `--color-text-secondary` | `#1a1e24` / `#566070` |
| 主色 | `--color-accent` | `#2457c5`，悬停 `#1a3f94` |
| 选中行 | `--color-row-selected` | `#eef3fd` |
| 正常状态 | `--color-ok` | `#1f7a45` |

- **字体**：正文用系统字体（`Segoe UI Variable`、`Microsoft YaHei UI`）。时间、路径和数字用 `Cascadia Mono`，同一列的数字才能对齐。
- **字号**：页标题 22px/700，区块标题 15px/700，正文 14px，表格辅助信息 12–13px。
- **圆角**：4 / 6 / 8px，分别用于标签、按钮、面板。
- **间距**：以 4px 为基准，常用 8、12、16、24px。

首期只做浅色主题。次要文字 `#566070` 在白底上的对比度大约 6:1，不要再调浅。

## 6. 候选状态与记录覆盖

| 状态 | 标签文案 | 样式 | 标签下方补充 |
| --- | --- | --- | --- |
| `recent` | 近期有使用 | 浅蓝底、深蓝字 | 无 |
| `stale_candidate` | 较久未记录 | 浅橙底、深棕字 | 无（距今天数写在“最近使用”列） |
| `never_observed` | 观察期内未记录 | 浅紫底、深紫字 | 无 |
| `insufficient_observation` | 观察不足 | 灰底 | 还需 N 天 |
| `unknown` | 无法判断 | 白底、虚线边框 | 具体原因，如“没有可匹配入口” |
| `excluded` | 已排除 | 灰底 | 长期保留 |
| `unavailable` | 已失联 / 暂不可访问 | 浅红底、深红字 | 具体原因 |

标签的文字本身就是状态，颜色只起辅助作用，色弱用户靠文字也能分清。任何地方都不能出现“可删除”“从未使用”这类结论。

记录覆盖用一个小圆点表示：实心是连续，半实心是有中断，虚线圆是未知。只有“较久未记录”和“观察期内未记录”两种状态显示覆盖，其他状态显示“—”。

概览的分布条用蓝、橙、紫区分近期、较久未记录、观察期内未记录，三色已用色板校验脚本检查过浅色背景下的色觉区分度。观察不足用灰色，无法判断用灰色斜纹，已排除和已失联用浅灰。图例必须带数字，不能只靠颜色。

## 7. 观察轨迹

详情面板里的一条横轴，回答“为什么判成这个状态”。从上到下依次是：

1. 阈值标签，写成“90 天阈值 · 07-13”。
2. 绘图区：
   - 最近 N 天的浅蓝底色，左边界是一条阈值虚线；
   - 灰色基线；
   - 记录缺口；
   - 每天的记录刻度；
   - 最近一次使用的圆点。
3. 坐标轴：起点、月份、今天。
4. 图例。
5. 缺口明细：最多列 3 条，更多的折叠起来。

绘制规则：

- **横轴**：起点取“当前观察起点”和“原始事件保留边界”中较晚的那个，终点是查询时刻。位置按 `(t - 起点) / (终点 - 起点)` 计算。
- **刻度**：按本地日期汇总，有直接记录的那天画一条 2px 竖线，同一天记录多次也只画一条。刻度只说明“那天有记录”，不代表使用时长或次数。观察超过 365 天时改为按周汇总，否则刻度会挤成一片。
- **最近一次**：在 `lastUsedAt` 的位置画圆点。如果它早于轨迹起点（原始事件已清理，或者属于旧的观察代次），圆点贴在左端，旁边写“更早：YYYY-MM-DD”。
- **缺口**：`gap` 画橙色斜纹，`unknown` 画灰色细斜纹。锁屏、休眠、空闲这类 `inactive` 区间不画，它们是能解释的非活跃期，不算漏记。短于 1 像素的区间按 2px 画；落在同一像素里的相邻区间合并。没开开机启动的电脑每晚都可能产生 `unknown`，所以必须合并，完整列表放在明细里。
- **阈值线**：`cutoff = 当前时刻 - 阈值天数 × 86400 秒`。cutoff 早于轨迹起点时（也就是观察不足），不画阈值线，在标题右边写“开始观察不足 90 天”。

几类特殊对象的画法：

| 对象 | 画法 |
| --- | --- |
| 观察期内未记录 | 只有基线和缺口，没有刻度 |
| 观察不足 | 整条轴都在阈值以内，不画阈值线 |
| 无法判断 | 基线改成虚线，下面写原因 |
| 已排除 | 只画到排除时刻，之后整段置灰 |
| 恢复观察后 | 从新的观察起点开始画，旧记录按“更早”处理 |

可访问性：绘图区设 `role="img"`，`aria-label` 用一句话写清起点、有记录的天数、最近一次、阈值后有没有记录、有哪些缺口。缺口除了颜色还有斜纹，打印成黑白也能分辨。

实现上建议封装成 `ObservationTrack.vue`。绝对定位的 `div` 或单个 SVG 都可以，输入类型见[接口设计文档](../docs/接口设计文档.md)第 4 节的 `ObservationTrack`。详情面板内宽约 280px，每天约 2px，131 天的轨迹能看清。

## 8. 列表交互

- 单击某行，在右侧打开详情，选中行显示浅蓝底。`↑`/`↓` 切换行，`Enter` 打开独立详情页，`Esc` 关闭详情。
- 默认按“最近使用”升序排列；没有时间的项无论升序还是降序都放在最后，和接口约定一致。
- 状态筛选是单选，数量来自后端在同一阈值下的统计，不是当前页的数量。
- 勾选“仅看记录连续的”后，只保留覆盖为 `continuous` 的项。
- 每页 50 条。“导出当前结果”导出当前筛选下的全部结果，不只是当前页。

## 9. 空状态、加载和错误

| 场景 | 展示方式 | 文案 |
| --- | --- | --- |
| 还没启用记录 | 概览顶部放引导区，配“添加文件夹”“启用记录”两个按钮 | 还没有开始记录。添加要观察的文件夹，再启用记录。 |
| 文件夹页没有观察范围 | 空状态 + “添加观察范围”按钮 | 还没有观察范围。添加一个本地文件夹后，浏览过的子目录会出现在这里。 |
| 筛选后没有结果 | 空状态 + “清除筛选” | 没有符合条件的项目。 |
| 加载中 | 表格显示 8 行骨架，筛选栏仍可操作；详情面板也用骨架 | 无 |
| 部分数据源不可用（503） | 列表上方黄色提示，已有数据保留 | 文件夹记录暂不可用，已有记录仍可查看。 |
| 查询失败 | 红色提示 + 重试按钮；不能拿旧数据冒充新结果 | 读取失败，请重试。 |
| 记录已暂停 | 顶栏灰点；概览顶部提示 | 记录已暂停，暂停期间会形成记录缺口。 |
| 浏览器预览（不在 Tauri 中运行） | 沿用现在的“浏览器预览”提示 | 无 |

| 原型部分 | 组件 |
| --- | --- |
| 外框、顶栏、导航 | 改造现有 `AppShell.vue` |
| 搜索 | `NInput`（可清空） |

| 仅看连续 | `NCheckbox` |

| 状态标签 / 覆盖圆点 | 自写 `StatusTag.vue`、`CoverageMark.vue`（`NTag` 的配色不好控制） |

主色通过 `NConfigProvider` 的 `themeOverrides` 设成 `#2457c5`，保证 Naive UI 组件和自写组件颜色一致。

## 11. 和当前前端的差异

现在的 `frontend/src/assets/main.css` 和 `AppShell.vue` 还是初始化阶段的绿色风格。按本方案需要改这些地方（都还没改）：

- 主色 `#285d45` 改为 `#2457c5`，背景 `#f7f8f6` 改为 `#f4f5f7`。
- 侧栏去掉 01–04 序号，改成图标加数量，底部显示观察起点。
- 新增顶栏，放采集状态和暂停按钮。
- 页标题从 30px 改为 22px；内容区内边距从 54/56px 收紧到 20/24px，给列表留出更多横向空间。
- 把 `styles.css` 里的变量搬到 `main.css` 的 `:root`。

## 12. 数据需求

- 列表：现有 `ObjectSummary` 已经够用。“还需 N 天”可以由 `observationStartedAt` 和阈值算出来。
- 状态计数：由 `get_overview` 按同一阈值返回。
